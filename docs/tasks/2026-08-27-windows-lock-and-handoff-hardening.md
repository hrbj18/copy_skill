# 单次开发指导文档：Windows 锁安全与项目交接加固

日期：2026-08-27

## 一、目标

消除 Windows 下任务锁存活探测向整个控制台广播 `Ctrl+C`、进而中断 pytest 与 Codex 后台进程的缺陷；同时建立轻量、当前、可审计的项目交接入口，使后续任务只加载必要上下文，不恢复损坏会话，也不扫描历史开发过程文档。

## 二、范围

1. 修复 `JobLock._pid_alive()` 的跨平台实现。
2. 增加 Windows 安全回归测试，证明存活探测不会调用 `os.kill(pid, 0)`，并覆盖活动 PID、无效 PID、同任务并发拒绝与陈旧锁恢复。
3. 建立 `docs/handoff/`，包含读取路由、当前状态、稳定产品规则、当前决策、代码地图和机器可读字符预算。
4. 将 `AGENTS.md` 维护为简短强制路由，保留安全、授权、历史文档和第三方边界。
5. 增加项目本地交接审计入口，并纳入 pytest 回归。
6. 在独立 Windows 进程中执行完整测试、doctor、CLI 帮助、计划任务只读查询和交接审计。

## 三、冻结决策

- Windows PID 探测必须使用无信号、无终止副作用的系统查询；不得使用 `os.kill(pid, 0)`。
- 非 Windows 平台继续使用 POSIX 的 signal-0 语义。
- 不新增重量级运行时依赖；优先使用 Python 标准库和 Windows API。
- 所有可能运行 pytest 的首次验证必须在独立隐藏进程中完成，确认修复有效后才允许普通回归。
- `docs/项目开发过程文档.md` 不作为输入读取；仅在全部实现与验证完成后追加本次事实记录。
- 旧任务指南均视为历史合同；当前代码、配置、本文件及 `docs/handoff/CURRENT_STATUS.md` 是本次权威状态。

## 六、安全边界

## 七、验收标准

3. Windows 活动 PID 返回存活，无效 PID 返回不存活；测试能证明 Windows 分支不调用 `os.kill`。
4. 交接审计通过：所需文件存在、字符预算合格、默认读取集明确、历史过程文档被禁止作为输入。
5. `doctor`、CLI 帮助和计划任务查询均能结束并给出可解释结果；只读环境或未安装计划任务可作为非阻断状态记录。
