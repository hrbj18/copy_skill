# 2026-08-27 工作台一键启动器

## 用户需求来源

用户在资源管理器中双击工作台相关 `.py` 文件没有反应，并且不愿使用全英文命令。项目必须在根目录提供可直接双击的 `启动工作台.bat`。现有 `科技内容情报工作台.cmd` 使用 `start` 和 `pythonw` 静默启动，导入、环境或 Tk 启动失败时没有可见证据，必须一并收敛到可靠启动链路。

## 目标

- 用户从资源管理器双击 `D:\work\copy_skill\启动工作台.bat` 即可启动中文工作台。
- 启动器从任意当前目录都先切换到自身所在项目根目录。
- 只使用项目 `.venv\Scripts\python.exe`，通过 `-m douyin_intelligence.cli workbench` 启动。
- 启动失败时显示中文原因、真实退出码和有限启动日志路径；不得静默退出。
- 连续双击只保留一个工作台实例。
- 旧入口 `科技内容情报工作台.cmd` 与新入口复用同一实现。

## 冻结范围与架构决定

1. 新增根入口 `启动工作台.bat` 和 ASCII 名称的内部 helper；两个中文根入口只负责调用 helper。
2. helper 使用 `%~dp0` 推导路径、`cd /d` 切换根目录，并设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`。
3. helper 不回退到系统 Python，不联网安装依赖；虚拟环境、配置或包入口缺失均非零退出。
4. 启动日志每次覆盖写入固定项目路径，不无限追加。错误输出在进入日志前做最小脱敏，日志不得包含密码、Cookie、Bearer、CDP/WebSocket 地址或浏览器认证材料。
5. CLI 的正式 `workbench` 分支使用项目自有单实例锁包装现有 `run_workbench`。锁冲突只提示已有实例，不杀进程、不按进程名操作 Python。
6. 正常启动使用控制台版项目 Python；工作台关闭后启动器正常退出。失败时保留窗口并等待按键；测试可用明确环境开关禁用等待。
7. 为真实 GUI 冒烟提供仅由测试显式启用的有界自动关闭参数；生产双击不自动关闭工作台。

## 交付物

- `启动工作台.bat`
- `scripts/launch_workbench.cmd`
- 可靠单实例与异常处理的项目自有启动模块/CLI 接线
- 与新入口一致的 `科技内容情报工作台.cmd`
- 聚焦测试、完整回归、真实 GUI 冒烟与安全扫描证据
- 更新后的当前 handoff

## 明确排除

- 不重做工作台 UI。
- 不修改浏览器会话生命周期、视觉 OCR、采集、热度排行或模型逻辑。
- 不自动启动浏览器、采集、OCR、模型调用或计划任务。
- 不安装、启用或运行 Windows 计划任务。
- 不修改 `third_party/MediaCrawler`，不读取浏览器 profile、Cookie、`.env.local` 或凭据。

## 安全边界

- 进程与锁相关首次聚焦测试、首次完整 pytest 必须在隐藏独立 Windows 进程组运行。
- GUI 冒烟必须有有限超时，只关闭本次明确启动的工作台进程，不触碰项目 Chrome、个人 Chrome 或 Codex 宿主。
- 不使用进程名批量终止，不使用 `os.kill(pid, 0)`。
- 日志固定大小/覆盖写入并通过敏感信息扫描。
- 调度器只读查询，保持未安装、未启用、未运行。

## 验收矩阵

1. 根目录准确存在 `启动工作台.bat`，从不同当前目录调用成功。
2. 启动链路使用 `%~dp0` 下的 `.venv\Scripts\python.exe` 和 `-m douyin_intelligence.cli workbench`，不直接执行包内 `workbench.py`。
3. 缺少虚拟环境时显示“项目虚拟环境不存在，请联系项目维护者”，非零退出，且不调用系统 Python。
4. 模块导入、配置或 Tk 启动异常写入有限日志并显示中文失败信息、退出码和日志位置。
5. 日志覆盖/截断且敏感扫描零发现。
6. 单实例锁阻止连续双击创建第二个工作台；不杀已有实例。
7. 真实 GUI 冒烟证明 Tk 主进程在有界时间内保持运行，并只关闭本次实例。
8. 启动前后项目 Chrome/采集/OCR/模型/计划任务无新增运行副作用。
9. 旧中文入口与新入口调用同一 helper。
10. 聚焦测试通过；首次完整 pytest 在隐藏独立进程组通过；handoff audit 通过。

## 真实验收与停止条件

- 只做一次受控 GUI 启动，等待窗口/主进程可观察，随后通过测试专用有界自动关闭结束。
- 若 GUI 在预算内不可观察，停止并报告已经证明的进程/日志证据，不无限等待、不重复并行启动。
- 若发现与当前 BrowserSession/OCR 改动冲突，停止并报告具体冲突，不回退或覆盖既有实现。
