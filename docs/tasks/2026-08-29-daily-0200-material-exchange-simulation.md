# 单次开发指导文档：每日 02:00 新闻素材发布协议与 8 月 28 日模拟验收

日期：2026-08-29  
状态：当前唯一开发合同  
生产者：`D:\work\copy_skill`  
消费者：OpenMontage（本轮只生成读取规则和做消费者模拟，不写入其目录）

## 1. 背景与必须纠正的基线

copy_skill 已具备抖音对标账号/可信账号采集、热点聚类和排行、事实证据整理、视觉素材获取、每日素材包装配等能力；上一任务也已生成一份结构有效的四条国内新闻素材包。但该包来自用户指定脚本，4/4 的 `heat_status` 都是 `not_supplied`，不能改名或复制后冒充“8 月 28 日真实热点排行榜”。

本任务模拟北京时间 2026-08-29 02:00 自动运行，业务日期固定为 2026-08-28。必须重新读取真实的 8 月 28 日发现/热度产物或执行有界真实采集，形成带可追溯热度状态的昨日候选，并为高价值题材获取合格图片。最终建立一套无需用户每天发送路径命令、可被 OpenMontage 按日期约定读取的稳定文件协议。

## 2. 本次唯一目标

在 copy_skill 内实现“每日新闻素材交换区 V1”，并完成一次 2026-08-28 的真实模拟发布：

1. 按北京时间上一自然日计算业务日期。
2. 从项目已配置且已批准的对标/可信账号与既有公共新闻信号中形成真实候选、聚类和热度证据。
3. 为高热/高价值候选整理事实素材和获取准确图片。
4. 将结果原子发布到固定中文日期目录。
5. 生成一份可复制进 OpenMontage 的长期读取规则文档。
6. 在不修改 OpenMontage 的情况下，用独立消费者模拟只依赖“交换区根目录＋业务日期”找到、验证并读取素材包。

本轮不安装 02:00 Windows 定时任务，不开发 OpenMontage 正式导入器，不运行任何付费视频生产。只有本次模拟和协议验收通过后，后续任务才能安装调度或修改 OpenMontage。

## 3. 冻结角色和边界

- copy_skill 是唯一生产者，负责发现、热度证据、事实材料、图片和发布合同。
- OpenMontage 是消费者，未来负责选出最终 3—4 条、双主持写稿、冷审、镜头规划和视频生产。
- copy_skill 不得写入 `D:\codex_work\OpenMontage`；消费者只能只读交换区，再把已选资产复制进自己的项目缓存。
- 抖音标题、字幕、互动数据和模型输出只属于发现/热度证据，不属于事实证据。
- 新闻事实仍要求一条官方/第一方来源，或两条独立可靠来源；不满足者保留为 `research`，不得伪装成可播事实。
- 不读取或输出 `.env.local`、Cookie、浏览器档案、密码、二维码或 API key。可以通过项目既有安全入口使用登录态，但不得导出登录材料。
- `third_party/MediaCrawler` 保持零修改。

## 4. 北京时间和业务日期合同

模拟参数冻结为：

```text
simulated_run_at = 2026-08-29T02:00:00+08:00
timezone = Asia/Shanghai
business_date = 2026-08-28
content_window = 2026-08-28T00:00:00+08:00 .. 2026-08-28T23:59:59.999999+08:00
```

生产命令必须支持显式 `--business-date 2026-08-28`，测试不能依赖修改系统时间。未来不传日期时，只有“昨日模式”才能按当前北京时间减一自然日，不能用滚动 24 小时代替。

内容发布时间应落在业务日期窗口内。较晚抓取到的原文可作为事实证据，但不得把 8 月 29 日新事件倒灌进 8 月 28 日热点；事件归属、内容发布时间与抓取时间必须分别记录。

## 5. 固定交换区协议

根目录冻结为：

```text
D:\work\copy_skill\output\每日新闻素材\
```

结构冻结为：

```text
output/每日新闻素材/
  OP每日素材读取规则.md
  latest.json
  .staging/
  2026-08-28_每日素材/
    current.json
    packs/
      <run-id>/
        _READY.json
        昨日热点素材简报.md
        daily-material-pack.json
        package-manifest.json
        consumer-dry-run.json
        stories/<story-id>/
          story.json
          文案素材.md
          primary.<ext>       # 合格时存在
          backup-01.<ext>     # 合格且不同构图时存在
        openmontage/
          hotboard.json
          benchmark_accounts.json
          content_candidates.json
          run_report.json
```

规则：

- 中文日期目录采用 `YYYY-MM-DD_每日素材`，不得使用无年份的“8月28日”。
- 每次发布生成不可变的 `<run-id>` 包；不得原地修改已 READY 的包。
- `current.json` 在包校验完成后原子更新，指向该日期当前有效的相对包路径和 manifest SHA-256。
- 根级 `latest.json` 仅方便人查看最新成功日期；OpenMontage 正式读取必须按自己的业务日期定位，不能用 latest 替代精确日期。
- `.staging` 永远不可被消费者读取；失败阶段保留脱敏诊断或按现有 TTL 清理，但不得出现 READY。

## 6. `_READY.json` 与状态语义

`_READY.json` 只能最后生成，至少包含：

- `contract_version`、`producer`、`business_date`、`run_id`、`generated_at`。
- `status: success|partial`；失败包没有 READY。
- 人读/机器合同/manifest 的相对路径。
- story 数、可播候选数、有主图故事数、图片数。
- 热度信号摘要、事实证据摘要和缺失项。
- `package_manifest_sha256`。
- LLM/ASR/音频/抖音浏览器调用次数与请求/耗时预算。
- `openmontage_modified: false`、`rights_review_required`。

`partial` 是可消费状态，但报告必须解释是缺图、单账号信号、登录、外站或证据不足。消费者不得把 `partial` 等同于失败，也不得忽略其风险字段。

## 7. 昨日热点与候选选择

### 7.1 数据来源

- 优先使用项目当前启用的对标/可信账号和已存在的热榜/新闻源；账号必须有稳定 ID，不按模糊昵称串号。
- 若登录或外部平台不可用，遵守一次有界降级和停止规则，不反复开窗、扫码或重试。
- 允许对已聚类的具体新闻做受控的官方/可靠媒体原文查询和图片获取；不开发通用搜索 Agent，不做漫无目的全网搜索。

### 7.2 排序与诚实标签

同一事件跨账号/来源聚类后，分别记录：

- 账号覆盖数与账号列表。
- 总播放/点赞/评论/分享等实际可得互动，缺失保持 `null`。
- 最高单条热度及来源视频。
- 发布时间和新鲜度。
- 公开热榜/国内新闻源的额外关注信号。
- `heat_status`: `measured_multi_signal`、`measured_single_account`、`public_signal_only`、`not_supplied`。

任何缺失数据不得由模型补齐。事实证据只改变 `evidence_status` 和可播状态，不得回写或篡改热度排序。

### 7.3 数量策略

- 目标交付 6 条非重复候选，供 OpenMontage 最终选择 3—4 条。
- Top 1—4 力争每条 1 主图＋1 备用图；第 5—6 条至少争取 1 张主图。
- 最低真实验收：至少 4 条带真实发现/热度证据的候选，其中至少 3 条满足事实门并有合格主图。
- 若真实数据不足，允许少于 6 条并输出 `partial`，但不得用低价值旧闻、错误日期或虚构热度凑数。

## 8. 每条新闻素材合同

每条 `story.json` 和 `文案素材.md` 至少包含：

- 稳定 `story_id`、标题、业务日期、事件时间/发布时间、编辑候选顺序。
- 热度状态、排序、账号覆盖、实际互动和每项热度证据。
- `evidence_status`、confirmed facts、pending verification、claims to verify、`do_not_claim`。
- 官方/可靠原文 URL、来源名称、抓取时间和用途。
- 面向 OpenMontage 的素材摘要、普通用户价值、可用角度和视觉意图；这不是最终双主持台词。
- `material_status: ready|research|partial`。
- 图片的主体/事件/画面可用性三道门、主/备用角色、相对路径、SHA-256、像素、MIME、来源、署名、权利状态、构图/裁切提示和逐图 QA。

短视频/社交 UI 截图、旧事件人物照、头像、纯 Logo、二维码、泛化品牌图、低清图、错误事件和感知近重复不得进入主/备用。图片准确性优先于数量；所有外部图片默认 `review_required`。

## 9. OP 长期读取规则文档

必须生成根级 `OP每日素材读取规则.md`，内容要足以被复制进 OpenMontage 后长期使用，至少冻结：

1. 生产者/消费者职责和根目录。
2. 北京上一自然日的日期算法。
3. 日期目录、current、READY 和 manifest 的解析顺序。
4. 缺目录、无 READY、partial、过期和合同损坏的处理。
5. `story_id` 映射规则，禁止只按标题连接。
6. 热度与事实证据的边界。
7. confirmed/pending/do_not_claim 的写稿和冷审用法。
8. accepted 图片、缺图降级和权利复核规则。
9. 路径穿越防护、哈希校验、只读源包和资产复制规则。
10. 以 run_id＋manifest SHA 做幂等导入。
11. OpenMontage 仍负责最终选题、模型写稿、冷审、镜头和发布；素材包不能越权触发付费阶段。
12. 规则文档复制进 OP 后，必须由其 AGENT_GUIDE/每日快报路由显式引用；仅把文档放入目录不等于会自动读取。

规则文档不得包含当前单次测试的临时绝对包路径作为唯一入口；只允许固定交换区根目录和日期算法。

## 10. CLI、工作台与调度准备

新增或扩展一个稳定 CLI（实际命名可微调但语义不得改变）：

```powershell
python -m douyin_intelligence.cli daily-material-exchange simulate --business-date 2026-08-28
python -m douyin_intelligence.cli daily-material-exchange inspect --business-date 2026-08-28
```

`simulate/publish` 负责有界生产和原子发布；`inspect` 充当未来 OpenMontage 的只读消费者模拟，只能从根目录和日期解析 `current.json`，验证 READY/manifest/hash/path 后输出消费报告，不得依赖硬编码 run-id。

中文工作台新增或复用清晰入口“模拟凌晨2点生成昨日OP素材”和“打开昨日素材”，显示业务日期、阶段、状态、候选/图片数量、输出路径和错误；重复点击由原子锁拒绝。不得安装计划任务，本轮只确保命令接口未来可被调度器调用。

## 11. 性能、安全与故障边界

- 完整模拟必须在 60 分钟硬上限内结束，目标 30 分钟内；新闻采集、事实取证、图片获取分别有子预算。
- 每个网络、浏览器、模型和子进程调用有有限超时；保留完成故事，单项失败不丢整包。
- 项目浏览器最多一个受控实例/登录窗口；任务不得反复打开窗口。任务拥有的页面按既有生命周期关闭，用户手动登录窗口不得被粗暴终止。
- 默认不调用 LLM 验证事实。若复用既有 LLM 仅做文字整理，必须记录调用次数、模型路由和超时，且不得让模型生成热度、互动或事实。
- 不启动 RunningHub，不调用 OpenMontage 付费阶段，不安装调度任务。
- 发布器、消费者模拟、锁或子进程有变更时，聚焦与完整测试须按 RUNTIME_SAFETY 在隐藏独立 Windows 进程组执行。

## 12. 任务拆分和实施顺序

1. 只按交接路由定位现有排行、可信账号、证据、视觉锚点、每日包、锁和工作台入口。
2. 定义交换区路径、日期算法、READY/current/latest 数据合同和状态机。
3. 实现不可变 pack＋原子 current/latest 发布器、路径/哈希验证和消费者 inspect。
4. 实现从现有真实排行/报告到素材 selection 的有界装配；保持 heat/evidence 分离。
5. 复用视觉锚点和每日素材包，为选中候选获取/装配图片与文字材料。
6. 生成 OP 长期读取规则文档和每条中文文案素材。
7. 加入 CLI、中文工作台入口、重复运行保护和状态展示。
8. 先运行静态和聚焦测试，再执行 2026-08-28 真实模拟。
9. 逐条审查热点证据、事实来源和全部最终图片；执行只读消费者 dry-run。
10. 完成相关/完整回归、敏感扫描、边界检查和 handoff 收尾。
