## 1. 目标

把当前原型推进为可独立运行的普通项目流程：针对三个已提供的抖音对标账号，通过真实抖音接口批量获取作品结构化数据，对账号身份和结果做强校验，从跨账号候选中筛选高价值作品，仅下载高分视频，提取视频技术信息和音频转写，并生成可供后续视频项目消费的 Markdown 素材文档。

最终交付形态仍是 Codex Skill，但本轮优先完成和验证普通项目功能，Skill 只补充稳定入口，不主导架构。

## 3. 核心决策

1. MediaCrawler 保持完整、隔离、固定提交的上游部署，不修改其源码；它负责通过浏览器登录态调用抖音 Web API并落盘 JSONL。
2. 账号采集输出按一次运行的唯一目录隔离，禁止继续读取此前裸 ID 实验产生的串号数据。
3. 项目提供持久 Chrome/CDP 启动和 MediaCrawler 运行适配器，在项目层设置非默认 CDP 端口，不再手工修改上游配置。
4. creator 采集成功必须同时满足：进程成功、目录有作品、单账号内部作者哈希唯一、不同目标账号作者哈希不同、不同账号不能返回完全相同的作品 ID 集合。任一失败都不得进入素材生成。
5. 先采元数据并评分，再下载跨账号 Top N；默认开发验收下载 3 条，配置允许后续扩大。禁止为验证功能无差别下载所有作品。
6. 媒体下载使用 MediaCrawler 已落盘的结构化 `video_download_url`，项目负责重试、原子落盘、文件大小与 ffprobe 校验；不依赖截图或视觉点击获取视频。
7. 使用本地 faster-whisper 进行中文语音转写，默认 `small` 模型、CPU int8，可配置模型和设备。无语音或转写失败时保留标题/描述并显式标记，禁止伪造 transcript。
8. Markdown 由确定性代码生成，不要求本轮提供付费模型 API。内容包括来源、发布时间、互动指标、价值分、原始描述、完整转写、可复用开头、要点、选题角度、媒体技术信息和事实核验警告。
9. 抖音素材仅是选题、表达和热度信号，不作为新闻事实证据；Markdown 必须保留此警告。
10. JoeanAmier/TikTokDownloader 当前官方仓库明确说明加密参数算法已失效，因此不进入本轮关键路径。完成现有主链路后再决定是否部署其他下载器作为可替换 provider。

## 4. 交付内容

- 更新项目配置：三个账号的规范身份、采集运行参数、媒体选择与转写参数。
- 项目自有的 MediaCrawler 启动适配器，不修改 `third_party/MediaCrawler`。
- 新增普通项目命令：
  - 启动或检查专用持久浏览器；
  - 执行一次隔离 creator 批量采集；
  - 对一次采集进行身份/串号校验；
  - 从元数据筛选、下载、探测、转写并生成 Markdown；
  - 一个端到端命令按顺序执行以上阶段，并输出机器可读报告。
- 输出目录建议：
  - `data/raw/mediacrawler/runs/<run-id>/creator/<account-id>/...`
  - `data/media/<run-id>/<video-id>/video.mp4`
  - `output/materials/<run-id>/<score>_<account>_<video-id>.md`
  - `output/materials/<run-id>/summary.md`
  - `output/materials/<run-id>/run_report.json`
- 单元测试、失败路径测试和至少一次三账号真实运行报告。
- 更新现有 Skill，使其调用普通项目入口，并把详细输出契约放入相关 reference。

## 5. 明确排除

- 不访问、不修改 `D:\codex_work\OpenMontage`。
- 不加入定时任务，不创建凌晨自动化；稳定运行后另开任务。
- 不自动处理验证码、手机验证或风控挑战。
- 不读取、打印、复制或提交 Cookie、浏览器存储和 API Key。
- 不下载评论、不批量下载全部历史视频、不做视频画面 OCR。
- 不使用 LLM 改写成最终发布稿；本轮 Markdown 是可追溯素材与结构化选题草案。
- 不把抖音口播或字幕当作事实来源。

## 6. 安全与许可证边界

- MediaCrawler 仅用于本地内部研发验证，遵守其非商业学习许可证及平台条款；未来商业部署必须解决授权或更换采集 provider。
- 限制单账号作品数量、并发数和下载 Top N，保留合理请求间隔。
- 浏览器资料、媒体文件、原始数据、模型缓存和输出均不得提交到版本控制。
- 下载与输出采用临时文件后原子替换；失败不得覆盖上一次成功结果。

## 7. 验收测试

### 离线自动化测试

- 配置校验能拒绝裸公开 ID 伪装成 `sec_uid` 的 creator URL。
- 采集命令必须通过项目 runner 使用配置的 CDP 端口和运行隔离目录。
- 身份校验能复现并拒绝“三个账号返回相同 3 条作品”的假成功情况。
- 高价值排序在相同输入下确定性一致，并能跨账号限制数量。
- 下载器支持重试、原子写入、已存在有效文件跳过、无效 MP4 拒绝。
- ffprobe 结果能写入媒体元数据。
- 转写器成功、无语音、模型不可用和中断四类结果均有显式状态。
- Markdown 文件名安全，字段齐全，正文不包含 Cookie、临时下载 URL或其他秘密。
- 既有测试全部通过，Skill validator 通过。

### 真实验收

- 三个规范 `sec_uid` 均发起 creator 采集，每个账号至少得到 1 条作品，或明确报告平台返回空数据。
- 非空账号内部作者哈希唯一；不同账号作者哈希不得相同；作品 ID 集合不得完全相同。
- 从通过校验的候选中选取最多 3 条高价值视频，下载后的 MP4 可被 ffprobe 打开且时长大于 0。
- 对含语音视频生成非空转写；无语音内容明确降级。
- 生成至少一份 `summary.md` 和对应单视频 Markdown，能够仅依靠文档理解选题、原始口播/描述、热度依据和可继续创作的角度。
- 端到端报告区分成功、部分成功和失败，不能把串号、空结果或转写失败记为成功。
