# 单次开发指导文档：大厂重大动作的公司与事件优先级

## 目标

在已具备正文详情的公开科技事件中，稳定优先保留用户真正关心的大厂重大动作。优先级必须同时满足“已识别的重点公司/产品系”和“有明确重大科技动作”；公司名称本身不等于新闻价值，也不等于事实核验。

## 冻结决策

- 第一层重点公司为 AI 与算力核心主体：OpenAI、Anthropic、Google/DeepMind、Meta、微软、英伟达，以及阿里/Qwen、腾讯/混元、DeepSeek、字节/豆包、百度/文心、智谱、MiniMax、月之暗面/Kimi。
- 第二层为消费科技、具身智能与自动驾驶主体：华为、小米、苹果、特斯拉、小鹏、比亚迪，以及配置中明确列出的机器人头部主体。
- 只有模型发布/开源、芯片与算力、AI 安全、具身智能、智能驾驶、系统/平台级上线或重大产品能力更新等动作可获得公司优先级加分。
- 普通机型、耳机、手表、笔记本、价格、促销、售罄、海外例行发布、常规修复和游戏，即使命中重点公司，也不得因为公司优先级升档。
- 加分只影响公开事件的读者榜候选排序与有限事件池的选入，不改变原始抖音候选的互动、`heat_score`、`heat_rank`、`delivery_rank`、真实性状态或素材流程。
- 每项公司匹配、层级、动作依据、排除原因和计算得分必须留在 JSON；人读 Markdown 只展示自然新闻标题与简述。

## 实施任务

1. 在配置中定义可审计的公司/产品别名、层级、加分和禁止升档的普通消费品锚点；不新增网络来源或密钥。
2. 为公开事件增加确定性的“公司匹配 + 动作相关性 + 排除理由”评估，保留原始来源重要度与独立的读者投递分。
3. 让有限事件池和无抖音传播信号时的读者榜后备排序使用投递分；有同日抖音信号时仍由该信号优先排序。
4. 编写离线测试，覆盖第一层模型发布升档、第二层智能驾驶升档、重点公司普通耳机/售价不升档、非重点公司的重要事件不被删除、抖音热度不变、JSON 审计和人读文件隔离。
5. 运行聚焦测试、完整 pytest、compileall、CLI doctor、真实单日运行、inspect、读者榜验收和 handoff audit。

## 验收标准

1. 同源同动作强度的合格事件中，第一层重大动作高于第二层，第二层高于未命中公司；普通消费品事件不因公司命中获得加分。
2. 每个公开事件 JSON 中都可看到公司优先级判定、匹配锚点、动作判定和投递分；原始抖音计算字段在前后保持不变。
3. 抖音传播信号存在时仍优先决定读者榜顺序；无信号时才按投递分后备排序。
4. 人读 `每日科技热点榜.md` 仍无 URL、来源、抖音、热度、真实性或处理话术，且不因加权使用宣传腔。
5. 不满足二十条详情卡时维持 `partial`，不以重点公司普通新闻凑数；所有请求、浏览器与模型预算维持有限。
6. 所有测试和真实运行结论独立记录；不以 fixture 或旧包冒充线上验收。
