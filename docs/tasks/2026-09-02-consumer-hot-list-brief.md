# 单次开发指导文档：消费端科技热榜简报

## 目标

将 V2.4 交付包内面向人阅读的 `每日科技热点榜.md` 改为简洁中文新闻榜。它应像微博热榜的摘要页，只让读者看到按既有官方事件顺序排列的新闻标题和一至两句事件简介。

## 冻结范围

- 保持文件名、业务日目录、不可变包、官方事件排序和机器合同不变。
- 人类榜单每条仅输出排名、简洁中文标题与最多两句简述；不出现来源链接、发布日期、传播信号、热度、真实性状态、模型状态、提示语、原始英文标题或“据输入摘要”等来源话术。
- `official-discovery.json`、`candidate-pool.json`、`run-report.json` 与 `_READY.json` 继续完整保留来源、日期、信号、状态和审计字段，供程序、编辑复核与故障诊断使用。
- 中文模型仍只接收已归因的标题、摘要、日期和既有理由；只允许压缩/翻译，不得补充事实。模型失败时，机器审计必须如实记录，榜单不得伪造内容。

## 实施任务

1. 收紧中文卡片提示与校验，要求使用自然、直接的新闻句式，拒绝来源元话术和冗余背景。
2. 重写消费端 Markdown 渲染器，使其只读中文卡片的标题和摘要，不触碰审计字段。
3. 补充测试，覆盖：不泄露来源/信号/日期、无原始英文标题、事件仍可由审计 JSON 追溯、模型输出含元话术时回退。
4. 使用 2026-09-01 进行一次受预算限制的真实运行，核对新榜单、机器审计、不可变热度和浏览器清理状态。

## 安全与停止条件

- 不读取 `.env.local`、Cookie 或浏览器档案，不修改 OpenMontage、调度器或 `third_party/MediaCrawler`。
- 不修改既有不可变包；真实运行产生新的同日包。
- 网络、模型和浏览器均沿用既有有限预算。官方来源/中文模型不可用时诚实降级，不将来源证据写回消费端榜单。

## 验收标准

1. 人类榜单最多十条，每条只有中文标题和一至两句新闻简述；不存在 Markdown 链接、URL、日期、`来源`、`抖音`、`传播信号`、`not_found`、`据输入摘要`、`官方来源`、热度和真实性提示。
2. 正常模型输出的标题与摘要含中文，不以原始英文标题或来源原话作为消费端正文。
3. 同一包的 `official-discovery.json` 仍含来源、日期、信号和原始可追溯字段；人类榜单的事件顺序不变。
4. 原有候选 `heat_score`、`heat_rank`、`delivery_priority_score`、`truth_status` 与官方事件隔离关系保持不变。
5. 聚焦测试、全量 pytest、compileall、CLI help、doctor、pack inspect 和 handoff audit 通过。
6. 真实运行在 3,600 秒内结束，浏览器页面和租约归零；外部采集不足时包如实标为 `partial`。

## 完成定义

只有当新消费端榜单和审计 JSON 明确分工、上述验证完成、handoff 更新且开发历史通过追加脚本记录后，才标记任务完成。
