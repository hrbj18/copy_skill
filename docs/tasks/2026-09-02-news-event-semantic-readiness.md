## 1. 任务背景与已验证问题

2026-09-01 当前包 `run-20260901-033c86d2ed61` 已解决明显的跨事件误聚类，并为 33 个候选保留内容证据，但人类简报前列仍出现以下标题：

1. `MiniMax H3模型实测内容`
2. `Microduck国内低成本复刻方案预告`
3. `国产大模型教程引发AI圈热议`

代码与产物核对确认存在两类独立缺陷：

- `story_enrichment` 当前主要按文本字符数判断提取是否成功；第一条只有视频标题级证据，也能因长度达到阈值而成为 `success`。这只能证明“有文字”，不能证明“形成了新闻事件”。
- 第二条原始平台描述已包含主体、动作、对象、方案变化和预计发布时间，但模型输出合同没有强制保留事件要素，最终把完整描述压缩成模糊标签。

因此，本任务不是普通标题润色。必须在内容证据与人类简报之间新增可审计的“内容类型判断—事件要素提取—新闻完整度闸门—标题生成”语义层。

## 2. 本次开发目标

建立一个不会把视频包装标题直接冒充新闻标题的交付合同：

1. 区分具体新闻事件与评测、教程、观点、盘点、项目展示等科技内容。
2. 从现有抖音文字、OCR、ASR 和同事件视频中提取“谁在何时对什么做了什么”。
3. 只有达到事件完整度要求的候选才能进入“昨日科技新闻候选”。
4. 高热度但不属于新闻或信息不足的内容继续保留在独立区域，不删除、不篡改热度。
5. 标题必须由有证据支撑的事件字段生成；缺失信息不得由模型猜测。
6. 对高价值但信息不完整的候选按需补充提取，同时维持整套日常流程不超过 3600 秒。

## 3. 冻结原则与边界

### 3.1 必须保持的既有合同

- 抖音只提供发现、创作者表达和公开热度证据，不提供事实真实性证明。
- 全部候选继续保持 `truth_status: not_checked`，OP 仍负责后续事实核验。
- `heat_score`、`heat_rank`、原始互动量和来源矩阵证据不得被内容类型、模型摘要、图片或完整度修改。
- 既有 `delivery_priority_score` 与 `delivery_rank` 保持确定性；本任务新增的是交付分区和新闻资格，不得偷偷重算原始热度。
- 纯游戏排除、同源矩阵折算、事件聚类、同日晋升和历史不可变包规则保持不变。
- 不修改 `third_party/MediaCrawler`，不写入 OpenMontage，不读取或暴露凭据、Cookie、浏览器配置和 `.env.local`。

### 3.2 明确不做

- 不核验新闻真假，不联网补写官方结论。
- 不把高赞、多个账号转载或模型自信度当作事实可信度。
- 不要求所有评测、教程和观点退出候选池；它们只是不进入主新闻区。
- 不为了补齐字段而虚构人物、日期、版本、性能、价格或因果关系。
- 不在本轮修改配图搜索质量；图片沿用现有 Top 3 规则，并在新的新闻交付区内明确其审核状态。

## 4. 目标数据合同

在现有 story 字段上增量增加以下结构，保持 V2.0/V2.1/V2.2 读取兼容：

```json
{
  "content_type": "news_lead | creator_review | creator_experiment | tutorial | opinion | roundup | project_showcase | mixed | uncertain",
  "event_slots": {
    "subject": "有证据的主体或空字符串",
    "action": "发布、开源、更新、宣布、回应、测试等具体动作或空字符串",
    "object": "模型、产品、项目、政策或事件对象或空字符串",
    "time_text": "来源中明确出现的时间表达或空字符串",
    "event_status": "released | announced | upcoming | tested | rumored | discussed | unknown",
    "result_or_change": "有证据的结果或变化或空字符串"
  },
  "event_evidence_refs": [],
  "event_completeness": {
    "score": 0,
    "required_present": [],
    "missing": [],
    "quality_flags": []
  },
  "news_readiness": "ready | needs_enrichment | not_news | insufficient",
  "news_headline": "仅在有足够证据时生成",
  "headline_quality_flags": []
}
```

字段语义：

- `content_type` 复用项目既有双轨编辑思想，不发明与已有合同冲突的第二套真伪分类。
- `event_evidence_refs` 必须能回指 `content_evidence` 中的视频和提取方式；不能只有模型结论而没有来源。
- `event_completeness.score` 是结构完整度，不是事实可信度，也不参与热度计算。
- 旧的 `canonical_title`、`event_summary` 和 `key_points` 保留。新闻区优先显示 `news_headline`；非新闻区仍可显示内容型标题。

## 5. 新闻资格与标题规则

### 5.1 主新闻区最低资格

一条候选进入 `ready` 至少需要：

1. `subject` 非空；
2. `action` 是具体事件动作，而非“热议、来了、炸锅、值得关注”等包装词；
3. `object` 非空；
4. `content_type` 为 `news_lead`，或能够明确表达发布、开源、更新、宣布等事件的项目类内容；
5. 上述字段均能回指输入证据。

时间并非所有事件的强制字段，但只要来源给出了日期、相对时间或发布状态，就必须保留。相对时间需要同时保留视频发布时间作为解释锚点，不擅自换算成没有证据的精确日期。

### 5.2 标题生成

新闻标题从结构化字段生成，优先采用：

`主体 + 时间/状态 + 动作 + 对象/结果`

以下词语不能单独支撑主新闻标题：

- 实测内容、相关消息、最新进展、引发热议、方案预告
- 实测来了、重磅来袭、又进化了、AI圈炸锅、王炸

它们可以出现在来源原文中，也可以在字段完整时作为补充语义，但不得替代主体、动作和对象。标题校验器必须输出具体质量标记，而不是仅靠提示词约束。

### 5.3 信息不足时的处理

- 有评测行为但没有新事件：`creator_review` 或 `creator_experiment`，进入科技内容区。
- 有教程内容但没有明确发布事件：`tutorial`，进入科技内容区。
- 看似新闻但缺少必要字段：先标记 `needs_enrichment`；预算耗尽仍不完整则为 `insufficient`。
- 模型失败、输出缺字段、产生来源中不存在的数字或日期：拒绝该模型结果，回退到确定性结构或降级，不得把旧模糊标题包装成 `ready`。

## 6. 开发任务拆分

### 任务 A：冻结真实反例与基线

- 从当前 2026-09-01 不可变包中提取 MiniMax H3、Microduck、国产大模型教程三个最小脱敏 fixture。
- 记录实施前 241 个全量测试基线和当前简报输出，避免修复时破坏聚类、热度与交付合同。
- fixture 不包含临时媒体 URL、Cookie、凭据或私人浏览器数据。

### 任务 B：内容类型和事件要素模型

- 在项目自有 `src/` 下实现确定性字段规范化、内容类型枚举、事件完整度计算和标题质量标记。
- 明确区分“文本提取成功”和“事件结构完整”；旧 `extraction_status` 只描述取证过程，新增 `news_readiness` 描述交付资格。
- 对模型输出做严格 schema、类型、长度、数字来源和枚举校验。

### 任务 C：重构模型归纳合同

- 将 LLM 输入限制为现有 `content_evidence`、视频发布时间和已聚类来源，不允许联网或补充常识。
- 要求逐条输出内容类型、事件字段、证据引用、摘要和要点。
- 模型不得直接自由创作最终新闻标题；先通过字段校验，再由受约束逻辑生成或校验 `news_headline`。
- 数字、日期、版本、公司表态继续进入 `claims_to_verify`，不得因标题生成从待核验清单消失。

### 任务 D：按事件完整度触发补充提取

- 当前的“文字长度不足才 OCR/ASR”改为“文字不足或事件字段不完整时，按价值与预算决定是否补充”。
- 顺序固定为：完整平台描述 → 已有同事件支持视频 → 画面 OCR → 本地 ASR。
- 仅处理推荐顺序靠前、热度较高且有希望补齐的候选；达到 `ready` 后立即停止额外媒体处理。
- 所有浏览器、下载、OCR、ASR 和模型调用保持有限次数、有限并发与明确超时。
- 补充搜索如需增加，只能用已提取的具体实体/产品锚点做定向发现，不能用宽泛关键词漫游，也不能作为事实核验。

### 任务 E：人类简报双区输出

- `昨日热点图文简报.md` 和相关人类可读输出至少分成：
  1. `昨日科技新闻候选`：仅 `news_readiness=ready`；
  2. `高热度科技内容与待补充线索`：评测、实验、教程、观点、盘点、展示和信息不足项。
- 两区均显示原始热度、推荐顺序、来源视频、提取方式、真实性未核验声明和图片状态。
- 新闻区每条显示新闻标题、一句话事件摘要、关键点、为什么值得关注、缺失或待核验字段。
- 非新闻区明确显示内容类型和未进入新闻区的原因，不让用户误以为候选被删除。

### 任务 F：包合同、兼容与观测

- 在 manifest/run-report 中增加各内容类型数量、`ready/needs_enrichment/not_news/insufficient` 数量、标题质量失败数和补充提取次数。
- 旧包读取器必须在缺少新字段时安全降级；不得重写历史不可变包。
- OP 使用的稳定入口与目录规则保持不变；新字段为增量兼容。
- 只有通过同日质量门的新包才能晋升 `current/latest`。

### 任务 G：测试、修复与真实验收

- 先跑新增聚焦测试，再跑全量 pytest、compileall、CLI 离线检查和 handoff audit。
- 用冻结的 2026-09-01 原始输入离线重放，检查 33 条候选的分区、标题和热度不变性。
- 自动化通过后，再在认证可用且预算允许时执行一次不超过 3600 秒的真实业务日运行。
- 外部账号超时、搜索失败、无图或认证不可用必须诚实标记 `partial/not_probed`，不得冒充完整线上验收。

## 7. 冻结验收样例

### 7.1 MiniMax H3 标题级线索

输入只有“MiniMax H3，还在进化，实测来了”等标题级文字时：

- 不得生成 `MiniMax H3模型实测内容` 作为新闻标题；
- 不得进入主新闻区；
- 应为 `creator_review`、`creator_experiment` 或 `needs_enrichment`；
- 只有补充证据明确出现新的发布、更新或官方事件后，才允许成为 `news_lead`。

### 7.2 Microduck 完整平台描述

当来源明确表达陆吾智能正在准备国产平替舵机、修改硬件电路、降低成本并预计两周内发布时：

- 主体、动作、对象、状态和相对时间必须被提取；
- 新闻标题应达到“陆吾智能预告将在两周内发布 Microduck 国内低成本复刻方案”这一信息完整度；
- 不要求逐字一致，但不得退化为“Microduck国内低成本复刻方案预告”。

### 7.3 “国产大模型教程引发热议”

- “引发热议”不能作为具体动作使其自动进入新闻区；
- 若来源能确认具体机构推出某教程，可生成“主体推出教程”的事件标题；
- 无法确认主体或发布动作时归入 `tutorial` 或 `insufficient`，不得补造机构名称。

## 8. 自动化验收标准

1. 主新闻区 100% 标题具有非空主体、具体动作和明确对象，并能回指内容证据。
2. 来源明确提供时间或事件状态的 fixture 中，结构化字段和标题/摘要 100% 保留该信息。
3. 模糊包装词不能单独通过新闻资格闸门；标题质量失败项为 0 后方可晋升。
4. 三个冻结反例全部满足第 7 节行为，且不存在来源外新增的人物、日期、数字、版本或结论。
5. 非新闻高热内容仍保留在第二分区，原始热度、互动、来源视频和推荐排名不丢失。
6. 对同一离线输入，原有 `heat_score/heat_rank` 完全不变；新语义字段不得进入热度公式。
7. 模型禁用、超时、返回非法 JSON、缺字段或新增来源外数字时，系统稳定降级且不把候选误标为 `ready`。
8. V2.0/V2.1/V2.2 旧包读取兼容测试通过；历史包没有被修改。
9. 聚焦测试、全量 pytest、compileall、CLI/doctor 与 handoff audit 全部通过。
10. 一次完整日常运行总墙钟时间不超过 3600 秒；浏览器最终页面和租约均为 0，临时媒体按现有规则清理。

## 9. 人工验收标准

从离线重放或真实运行中抽查至少 20 条，逐条回答：

1. 单看标题是否知道谁对什么做了什么；
2. 标题和摘要的每个具体人物、时间、数字、产品和动作能否在来源证据中找到；
3. 评测、教程和观点是否被正确分流，而非伪装成新闻；
4. 同一事件是否仍保持一条 story，未重新引入跨事件合并；
5. 高热但非新闻的内容是否仍可供 OP 作为选题灵感使用。

人工抽查不允许出现：跨事件拼接、虚构要素、模糊标题进入主新闻区、非新闻内容静默丢失。任何一项出现即视为未通过，修复后重新执行相关测试。

## 10. 运行预算与停止条件

- 全流程硬上限维持 3600 秒；新增语义整理优先复用已取得的文字，不得无条件下载全部视频。
- OCR、ASR、模型和定向补充发现必须有独立预算、超时、调用计数和降级路径。
- 若实现必须修改 OpenMontage、第三方 MediaCrawler、凭据或历史不可变包，立即停止并报告。
- 若模型无法在来源边界内稳定输出结构化字段，保留确定性降级和第二分区，不得降低证据标准换取表面完整率。
- 普通代码缺陷、fixture 失败、输出兼容问题和预算内的真实运行问题均在本任务范围内解决，不能以 `partial` 掩盖本地可修复缺陷。
