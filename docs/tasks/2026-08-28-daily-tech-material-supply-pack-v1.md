## 1. 背景与问题修正

项目已经具备抖音对标账号采集、画面文字/音频分流、新闻聚类与热度排序、大模型简报、新闻视觉素材获取、OpenMontage 旧版快照导出等能力，但这些能力仍是若干独立出口，尚未形成 OpenMontage 可直接消费的一份自包含“每日素材供应包”。

上一轮国内四条新闻素材测试证明受控网页来源可在约一分钟内取得多数合适图片，但必须修正两项结论：

1. “汤道生谈腾讯 AI”的现有图片是带视频界面语义的旧活动/视频截图。它只能证明人物身份，不能证明本次发文事件，且不适合作为成片新闻主图。因此该图在本任务基线中必须判为不合格，不得进入主图或备用图。
2. 用户观察到的约 40 分钟不是稳定运行耗时；其中包含恢复旧任务、修改代码、试探来源、反复运行、人工看图、回归测试与文档收尾。生产路径必须把一次普通运行限制为有界的资料装配任务，禁止借助开发代理、LLM 或漫无目的搜索来“边运行边开发”。

## 2. 本次唯一目标

在 copy_skill 内实现“每日科技新闻素材供应包 V1”：把已经形成的热点/候选新闻、事实证据和可用视觉素材按稳定故事标识装配为一份同时面向人和机器的自包含交付物，并提供中文工作台一键入口。

本轮目标不是替 OpenMontage 写稿、决定镜头、生成视频，也不是建立通用互联网搜索引擎。copy_skill 负责上游“发现、整理、提供证据与素材”；OpenMontage 后续仍负责主编决策和视频制作。

## 3. 冻结原则

1. 热点先保留，类型再分流，事实最后把关。抖音仅是发现/热度证据，不能充当新闻事实来源。
2. 不伪造热度。没有真实账号覆盖或互动数据时，必须写明 `heat_status: not_supplied`，可以作为用户指定新闻研究，但不得冒充热榜结论。
3. 不伪造素材完整度。找不到事件准确且可用的图片时允许 `partial` 或 `missing`，不得用 Logo、头像、二维码、泛化品牌图或错误事件截图凑数。
4. 主体一致不等于事件一致。人物、产品或机构命中只是第一道门；还必须分别通过事件匹配和画面可用性检查。
5. 所有图片默认 `review_required`；权利/署名信息必须随包传递，V1 不承诺获得商业授权。
6. 默认纯数据和网页图片流程，不调用 LLM、ASR、音频处理、抖音浏览器或登录态。只有明确输入已有上游产物；不得为补图自动打开浏览器。
7. 保存原始产物，供应包复制或引用校验后的文件，不覆盖原文件。

## 4. 范围

### 4.1 必须实现

- 新增稳定的每日素材包领域模型、构建器、校验器与 CLI。
- 把新闻记录按稳定 `story_id` 连接到热度、事实证据和视觉资产；严禁只用可变标题静默合并。
- 生成面向人的 Markdown 简报和面向机器的 JSON 合同。
- 生成自包含目录，包含故事级元数据、主图、备用图、SHA-256、相对路径、尺寸、来源、署名、权利状态、构图提示和缺失原因。
- 在包内生成或复用现有 OpenMontage 兼容快照，保持旧 `export-openmontage` 行为兼容。
- 新增快速模式与确定性缓存：默认仅处理已选择的 3–4 条新闻，每条最多 1 张主图和 1 张真正不同的备用图。
- 新增全局请求数、下载字节和墙钟预算；单来源失败不得拖垮整包。
- 中文工作台加入“一键生成每日科技素材供应包”入口，显示进度、最终状态、报告路径，并能打开报告/目录；沿用现有防重复运行机制。
- 使用国内四条新闻现有冻结输入完成一次真实装配验证，并重新执行逐图 QA。

### 4.2 明确不做

- 不改 OpenMontage 源码、配置或其工作目录；不实现下游导入器。
- 不安装定时任务，不自动发布，不启动收费调用。
- 不开发通用搜索 Agent，不爬全网，不接入新的付费图片服务。
- 不用大模型验证新闻真伪，也不用大模型参与图片下载。
- 不自动生成 AI 配图，不下载抖音视频作为成片素材。
- 不承诺所有新闻都有两张图；准确缺图优于错误补图。

## 5. 输出协议

默认输出目录：

```text
output/daily-material-pack/YYYY-MM-DD/<run-id>/
  daily-material-brief.md
  daily-material-pack.json
  package-manifest.json
  openmontage/
    hotboard.json
    benchmark_accounts.json
    content_candidates.json
    run_report.json
  stories/<story-id>/
    story.json
    primary.<ext>          # 仅在合格时存在
    backup-01.<ext>        # 仅在合格且不重复时存在
```

`daily-material-pack.json` 至少包含：

- 包版本、生成时间、业务日期、运行状态、输入来源、预算与实际用量。
- 每条新闻的 `story_id`、标题、选择来源、热度状态/分数/排序、账号覆盖和热度证据。
- 已核实事实、待核实项、`do_not_claim`、事实来源及其用途。
- 视觉意图、主图/备用图、相对路径、SHA-256、MIME、像素、来源 URL、来源站点、署名、权利状态、画幅/裁切提示、相关性与选中理由。
- `subject_match`、`event_match`、`visual_usability` 三个独立结果，以及最终素材状态和拒绝/缺失原因。
- OpenMontage 兼容快照相对路径与合同版本。

`package-manifest.json` 必须可独立校验所有包内文件的相对路径、字节数和 SHA-256，且不得包含绝对 Cookie、API key、浏览器档案或本机密钥。

## 6. 图片准入与淘汰规则

图片只有同时满足以下条件才可进入 `primary` 或 `backup`：

1. **主体匹配**：人物/产品/事件/地点与新闻视觉意图一致。
2. **事件匹配**：能够直接表现本条新闻事件，或被明确标记为可接受的当前产品官方图。人物旧照、其他会议现场即使人物正确也不得伪装成本次事件图。
3. **画面可用**：不是短视频播放器截图、社交平台 UI 截屏、二维码海报、头像、纯 Logo、聊天界面、明显水印拼贴、低清缩略图或大段无关文字页面。
4. **基本质量**：真实解码、MIME 一致、尺寸/字节达到既有安全阈值，且与同故事其他入选图不构成感知近重复。
5. **来源与权利可追溯**：保留原始页面/图片 URL、署名和权利状态；未知则标记 `review_required`，不能写成可商用。

人物新闻的优先级冻结为：本次事件官方文章头图/官方发布配图 > 同次事件权威媒体图片 > 与事件同时期且注明用途的官方人物资料图。短视频或社交 UI 截图永远不得作为最终图片；仅人物正确但事件错误时必须拒绝或降级为 `reference_only`，且 `reference_only` 不复制进最终主/备用文件。

上一轮汤道生视频截图必须成为回归夹具，确认会被拒绝。若在有限预算内没有找到本次发文的干净准确图片，该故事应诚实输出 `visual_status: missing` 或 `partial`。

## 7. 性能与缓存设计

### 7.1 快速路径

- 输入只包含已确认的 3–4 条新闻，不对未选择候选逐条补图。
- 每条默认最多 2 张最终图：1 主 + 1 备用；来源候选和请求数继续受配置上限约束。
- 复用现有 manifest、下载文件和 QA 时，必须先校验来源/内容指纹、文件存在、SHA-256 和当前准入版本。
- 缓存键至少覆盖：故事视觉意图、来源 URL/配置、图片筛选规则版本、最终图数量上限。
- 缓存命中不得再次联网；规则版本或输入变化必须使相关故事缓存失效，而不是复用旧判断。

### 7.2 预算

- 整包真实冷运行墙钟硬上限：5 分钟。
- 温缓存重建目标：15 秒内，网络请求数 0，已入选文件 SHA-256 不变。
- 每个网络/子进程调用必须有有限超时；达到全局预算后保留已完成故事并输出 `partial`，不得无限等待。
- 单故事/单来源错误隔离，错误须出现在报告中。

## 8. 命令与工作台体验

新增明确、可脚本化的 CLI（命名可在不改变语义的前提下微调）：

```powershell
python -m copy_skill daily-material-pack build --input <selection.json> --output-root <dir> --quick
```

CLI 必须返回有意义的退出码并打印最终状态、Markdown/JSON 绝对路径、故事/图片计数、网络请求数与耗时。`partial` 在包成功落盘且合同有效时不应被误报为程序崩溃；真正合同损坏才返回失败。

工作台中文入口必须：

- 自动选择“最新且符合合同的输入”，无法唯一选择时给出中文原因和建议，而不是静默猜测。
- 禁止重复点击启动同一任务；沿用进程/任务锁，且不得使用 `os.kill(pid, 0)`。
- 任务完成后展示 `success/partial/failed`、用时、故事数、图片数和报告路径。
- 提供打开 Markdown 报告和输出目录的操作，不自动打开或残留抖音/Chrome 窗口。

## 9. 任务拆分与开发顺序

1. **现状定位**：只根据交接路由定位现有 ranking/evidence、visual-anchor、OpenMontage exporter、CLI 和 workbench 入口，不扫描历史任务。
2. **合同与模型**：定义输入 selection 和输出 pack 的版本化数据结构、稳定 ID、状态机与校验规则。
3. **素材准入修复**：拆分主体/事件/可用性判定，加入视频 UI/旧事件回归拒绝，保持现有网络安全门。
4. **供应包装配器**：连接热度、事实和视觉产物，复制合格素材，生成 JSON/Markdown/manifest 和兼容快照。
5. **快速路径**：实现指纹缓存、零网络温重建、全局预算和故障隔离。
6. **CLI 与中文工作台**：增加构建/校验入口、状态展示和打开结果动作，不破坏现有按钮及启动器。
7. **自动化测试**：先聚焦新增模块，再执行相关回归和完整 pytest。
8. **真实验收**：用冻结的国内四条新闻运行冷/温两次，人工查看所有最终图片并核对报告。
9. **交接收尾**：更新当前状态与代码地图，必要时更新架构决定；追加一段开发记录但不得读取旧开发历史；执行 handoff audit。
