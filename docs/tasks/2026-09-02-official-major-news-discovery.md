状态：完成，验收通过

## 1. 背景与问题证据

现有 V2.3 的职责是从对标账号和八个宽泛抖音搜索词中，聚合视频并计算传播热度。其最近真实包有 33 个候选、34 条目标日视频，但对 `OpenAI / Astra / Anthropic / Fable / Mythos / World Labs / Atlas / 清朗 / AI-eSIM / Grok / Gemini / GB200` 的文本检索为零命中。该结果说明它没有发现这些事件，不能据此说明事件不存在或不重要。

原因已经确认：当前搜索词和对标账号只能捕获已被抖音账号表达的内容；事件尚未被转述、标题使用不同实体或传播较少时，永远不会进入候选池。现有 `truth_status: not_checked` 与 `fact_verification_requests: 0` 也明确表明，系统不具备外部事件发现或事实核验能力。

本任务改变的是“发现渠道”，不是把抖音热度包装成新闻事实。目标架构如下：

```text
配置化官方/权威公开源 -> 可归因的重大事件候选 -> 用实体定向检索抖音传播信号
                                                  \-> 独立的人类可读科技热点榜
既有抖音候选池 ----------------------------------> 保持原始热度与 OP 备选价值
```

## 2. 目标

在既有 `daily-material-exchange` V2 交付包中，增加一个有限、可追溯且可降级的“官方重大事件”通道，使每日素材包能同时提供：

1. 有原始公开链接、来源和日期的重大科技事件候选；
2. 每个事件对应的抖音传播信号，找不到也保留事件并明确写出；
3. 最多十条、不含 OCR 原文和视频标题堆砌的人类可读《每日科技热点榜》；
4. 原有抖音候选、`heat_score`、`heat_rank`、互动量、来源矩阵和真实性边界完全不变。

本轮仍**不**做新闻真伪裁决。`official_primary_source_attributed` 只表示事件卡片有一手公开来源，不等价于对全部描述、数字或未来结果的真实性担保。

## 3. 冻结范围与边界

### 3.1 纳入范围

- 新增配置化的官方/权威源目录，首批覆盖 OpenAI、Google Blog、GitHub Changelog、Anthropic News、World Labs Blog 和中国网信网 AI 相关公开页。
- 支持已有 RSS/Atom/JSON 与新增的受限 HTML 列表页解析；仅解析列表页已公开的标题、日期、简介和文章链接，不抓取正文，不使用搜索引擎抓取。
- 按业务日（北京时区）筛选、去重、分类和排序官方事件；对前四条定向发起有限的抖音实体查询。
- 写入独立的 `official-discovery.json`、增量的候选池字段和 `每日科技热点榜.md`，保留不可变包与稳定入口规则。
- 提供 fixture、单元/集成测试、离线回放和一次受预算限制的真实运行验证。

### 3.2 明确排除

- 不修改 `third_party/MediaCrawler`、OpenMontage、调度任务、账号凭据、Cookie、浏览器档案或 `.env.local`。
- 不让大模型联网、补写来源不存在的事实，且不要求模型决定新闻是否真实。
- 不抓取搜索结果页、社交媒体正文、受登录保护页面或任意 URL；不把抖音视频作为事实来源。
- 不修改历史不可变包，不因官方事件改变现有抖音候选的热度或排序。
- 不承诺每一天均有十条合格官方事件；来源失败或事件不足必须交付较少条目并标记 `partial`。

## 4. 数据与安全合同

### 4.1 来源记录

每个外部来源必须由配置声明：名称、入口 HTTPS URL、允许域名、格式、可信层级、文章路径前缀、解析上限和启用状态。请求必须满足：

- HTTPS、无用户名/密码、显式允许域名、公共 DNS 地址；
- 每请求超时、总请求数、总字节数、单页最大字节数和总墙钟预算；
- 跳转后的 URL 同样验证；错误写入来源错误清单，不中止当天其它来源。

每个事件必须持有 `source_refs[]`（名称、链接、发布时间、来源层级、提取方式），并有 `source_status`。没有合格来源或日期的条目不能进入业务日正式榜单。

### 4.2 排序与传播信号

- `official_importance_score` 只用于官方事件的交付顺序，由来源层级、确定性事件分类、发布时间和稳定 tie-break 构成。
- 仅前四条官方事件允许一次实体/产品锚点定向抖音查询；记录 `douyin_signal.status`、结果数和原始互动汇总。
- 已有故事的 `heat_score`、`heat_rank`、`delivery_priority_score`、`delivery_rank`、互动量和来源不得被新通道读写。
- 官方事件与抖音故事若有确定性实体/链接锚点重合，卡片只出现一次，并把抖音信号附在该事件下；不可靠的模糊词匹配不得合并。
- 同一业务日的提升质量门必须把官方事件数量和官方源错误数纳入非回归判断。新包的官方源错误增加或官方事件减少时，即使卡片合同修订号更高，也只能保留为审计包，不能替换覆盖更完整的当前包。

### 4.3 人类可读榜单

新建 `每日科技热点榜.md`，最多十张卡片，每张仅包含：

1. 简洁事件标题；
2. 一至两句可追溯摘要；
3. 为何值得关注；
4. 抖音传播信号（或“未找到定向传播信号”）；
5. 原始来源链接、日期与边界说明。

不得把 `screen_ocr`、整段视频描述、模型提示词、长符号表格或无来源的推测放入该文件。模型可在现有证据内压缩/翻译，但失败时必须用确定性、带原文来源的短回退文本。

## 5. 实施任务

### A. 官方来源采集与解析

1. 扩展项目自有 `news_sources.py`：保留 RSS/Atom/JSON 行为，新增受配置约束的 HTML 列表页提取。
2. 实现公共地址、跳转、字节和时限防护；解析失败返回可序列化错误。
3. 以 fixture 覆盖 OpenAI RSS、Anthropic News/World Labs Blog 风格 HTML、无日期、跨域链接、恶意 URL 和重复条目。

### B. 事件建模与官方排序

1. 在独立模块中把合格文章归并为可引用事件，按目标业务日筛选；不得把不同实体因泛词连接成一个事件。
2. 采用可解释的分类和重要度规则（模型发布、AI 安全、生成式内容、政策治理、消费产品、AI 基础设施等），记录理由与稳定排序键。
3. 输出完整的 `official-discovery.json`，包括原始文章、事件、排除原因、来源错误和预算用量。

### C. 与 V2 素材包的增量接入

1. 在 V2.4 中将官方事件、抖音信号和人类热点榜写入同一不可变包；V2.0--V2.3 读取器安全降级。
2. 对前四个事件调用已有项目搜索适配层，以事件的明确实体/产品锚点作为查询；所有失败保持事件且写清状态。
3. 不把官方事件混入旧 `candidates` 的热度公式；只添加新的 `official_major_events` 区域及 manifest 统计。

### D. 人类简报与回退

1. 实现短卡片渲染与确定性回退，确保官方源可读、可链接、无原始 OCR 垃圾文本。
2. 如启用既有模型，仅允许它处理已选事件的 `title/summary/source_refs`，输出必须校验后才采用；模型超时/非法输出时不影响包生成。
3. 面向中文交接时，模型成功输出的事件卡须包含受来源字段约束的中文标题、摘要和关注点；一次批量整理最多覆盖十条，不能增加来源外的数字、日期、人物、公司决定或能力结论。模型不可用、超时或输出不合格时，明确标记回退并保留原始来源文本，不能伪造中文改写。

### E. 测试、修复、验收

1. 先执行新增聚焦测试；再跑关联的 V2 套件和全量 pytest。
2. 通过 `compileall`、CLI help、doctor、pack inspect 和 handoff audit。
3. 用 2026-09-01 fixture 验证：当天的 OpenAI Astra、Anthropic Fable/Mythos、World Labs Atlas 风格条目能在其来源可用时进入官方候选；2026-09-02 的网信办条目不会被混入 9 月 1 日包。
4. 进行一次有明确预算的真实业务日运行。外网/抖音认证/图片等失败必须诚实为 `partial`，代码和本地测试可修的问题必须修复后重测。

## 6. 验收标准

### 自动化

1. RSS/Atom/JSON 原有测试保持通过；HTML 列表解析可稳定取出合格标题、日期、简介和同域文章 URL。
2. 非 HTTPS、私有/保留 IP、跨域跳转、超过字节上限和无日期的输入均被拒绝或不进入业务日榜单，且不导致整个运行失败。
3. 目标日 fixture 中，官方事件在无任何抖音匹配时仍被保留，`douyin_signal.status=not_found/partial` 明确可见。
4. 定向抖音查询数不超过四个事件和配置的查询/结果/墙钟预算。
5. 同一离线输入下，既有 `candidates` 的原始热度、热度排名、交付分值和来源证据逐项不变。
6. 官方事件与确定性同事件抖音记录不会重复出现在人类热点榜；模糊词相同的不同事件不会被错误合并。
7. 人类热点榜最多十条、每条有来源链接与日期，不含 `screen_ocr`、长原始视频描述或未经来源支持的数字；当来源整理模型可用时，交接卡片须是经校验的中文短卡片，模型不可用时则如实标注回退。
8. 模型禁用、超时、非法结构或来源失败时，包和热点榜均产生安全回退；旧 V2.0--V2.3 兼容测试通过。
9. 聚焦测试、全量 pytest、compileall、CLI help、doctor、inspect 和 handoff audit 全部通过。
10. 模拟“新修订包但官方入口暂时失败”的同日场景，验证它不会覆盖官方源更完整的当前包；官方事件更多、源错误更少的后续包可正常提升。

### 真实运行与人工检查

1. 整体运行硬上限 3600 秒，新增官方请求有独立预算；结束后浏览器页面与租约为零。
2. 实查前十条：每一条均能打开到它声明的来源页面，日期符合目标业务日，摘要不越过来源标题/简介的信息边界。
3. 每张卡片明确区分“官方来源归因”和“抖音传播信号”，不把前者写成已核验事实，也不把后者写成事实证明。
4. 若任一源失败、认证不可用或当日事件不足，结果标为 `partial` 或不足，不能伪称完成十条全网热点。

## 7. 运行预算与停止条件

- 默认最多 6 个官方入口、12 次外部 HTTP 请求、每次 20 秒、总下载不超过 6 MiB、官方发现阶段不超过 240 秒；定向抖音查询最多 4 个事件；中文卡片整理最多一次模型请求、十条事件和 1,800 输出 token，并纳入既有总 3600 秒硬上限。
- 不读取机密配置；不可达外部源、解析格式变化和抖音无命中都不是阻断，必须降级并记录。
- 如需要放宽来源白名单、抓取正文、引入搜索引擎、修改第三方或写入 OpenMontage，停止并单独报请用户决定。
