# 中转站本地配置与真实调用验证指导文档

日期：2026-08-26

## 目标

在不泄露 API 密钥、不修改 OpenMontage、不改动上游 MediaCrawler 的前提下，为当前项目完成海客（Sub2API）中转站的本地私密配置，并使用 `gpt-5.6-luna` 完成真实模型调用验证。

## 已确认事实

- 中转站服务地址为 `http://8.212.174.130:8080`。
- 项目的 OpenAI Chat Completions 适配器以 `/v1` 为基础路径，因此项目使用的 API Base URL 应为 `http://8.212.174.130:8080/v1`。
- 中转站官方“使用 API 密钥”说明要求 Bearer API Key 认证；项目当前实现与此一致。
- 后台密钥状态为活跃、永久有效，所属分组为 OpenAI。
- 后台密钥长度为 67 个字符，而修改前本地 `.env.local` 中的密钥长度为 66 个字符；此前 `401 INVALID_API_KEY` 的直接原因是本地密钥内容不完整，不是接口协议或代理问题。

## 本次范围

1. 修正项目根目录下被 Git 忽略的 `.env.local`，保存完整 API Key。
2. 在本地私密配置中设置：
   - `DOUYIN_LLM_BASE_URL=http://8.212.174.130:8080/v1`
   - `DOUYIN_LLM_MODEL=gpt-5.6-luna`
3. 使用项目自带 `llm-doctor` 验证认证和模型发现。
4. 使用项目的 `OpenAICompatibleAnalyzer` 或等价最小请求真实调用 `gpt-5.6-luna`。
5. 运行相关单元测试并检查密钥没有进入受版本控制的文件或输出。

## 排除项

- 不修改 `D:\codex_work\OpenMontage`。
- 不修改 `third_party/MediaCrawler`。
- 不创建、禁用、编辑或删除中转站后台密钥。
- 不执行抖音采集、视频下载或长文本批处理。
- 不将 API Key 写入 JSON、Skill、源码、测试输出或项目开发过程文档。

## 安全边界

- API Key 只允许存在于被 `.gitignore` 排除的 `.env.local` 或进程环境中。
- 诊断输出只报告是否配置、长度/不可逆摘要、HTTP 状态及脱敏错误，不输出密钥正文。
- 当前中转站仅提供明文 HTTP，配置必须保留显式 `allow_insecure_http`；正式长期使用仍建议迁移 HTTPS。

## 验收标准

- 本地读取的 API Key 与后台密钥具有相同长度和不可逆摘要。
- `llm-doctor` 不再返回 `INVALID_API_KEY`，能够获得模型列表。
- `gpt-5.6-luna` 的最小真实请求返回成功响应，并能解析模型文本。
- LLM 相关测试及完整项目测试通过。
- Git 状态和内容扫描证明密钥未进入受版本控制文件。
- 完成后仅向 `docs/项目开发过程文档.md` 追加本次开发记录，不读取或改写既有内容。

## 允许的最小偏差

- 如果 `/models` 不列出目标模型但服务端允许直接请求，可用成功的真实聊天响应作为模型可用性依据，并记录这一差异。
- 如果 Chat Completions 兼容端点拒绝目标模型，可在不改变用户指定模型的前提下诊断 Responses 端点，但不得擅自换用其他计费模型完成验收。
