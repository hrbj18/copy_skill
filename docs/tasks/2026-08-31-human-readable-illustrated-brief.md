# 单次开发指导文档：面向人的昨日热点图文简报

日期：2026-08-31

工作目录：`D:\work\copy_skill`

## 1. 目标

每日 V2 素材包除机器合同和完整技术审计稿外，新增一份适合人直接阅读、筛选选题的 `昨日热点图文简报.md`。简报按热度展示新闻事件，直接嵌入包内已经通过素材门槛的图片；没有合格图片时明确说明缺失，不以视频截图、泛化图片或错误事件图片补位。

## 2. 交付范围

1. 新增独立、确定性的图文简报渲染器。
2. 顶部提供日期、运行状态、候选数、配图数和热点速览表。
3. 每条事件只展示面向编辑的信息：标题、热度、摘要、最多四个要点、内容角度、待核验提示和来源视频。
4. 已获取图片使用包内相对路径以标准 Markdown 图片语法直接嵌入，同时显示图源、尺寸和 `review_required` 权利提示。
5. Top 3 无图时显示实际失败原因；排名 4 以后说明本流程未尝试配图。
6. 保留 `昨日抖音科技热点候选.md` 作为完整技术审计稿，保留 `candidate-pool.json` 作为机器合同。
7. 新包 `_READY.json` 的 `human_brief` 指向图文简报，并新增 `technical_brief` 指向详细稿；命令返回的 `brief_path` 和任务状态输出也指向图文简报。

## 3. 安全与兼容边界

- 不改变热度、排序、聚类、模型、OCR、图片搜索或图片质量门槛。
- 图片仍只处理 Top 3，且只嵌入实际存在于不可变包内的合格文件。
- 抖音材料仍是选题和公开热度线索，不是事实证据；简报显著保留未核验声明。
- `review_required` 不代表获得商业授权。
- 清理标题和摘要中的 Markdown 控制字符，避免不可信平台文本破坏文档结构或注入链接/HTML。
- 不修改历史 READY 包、OpenMontage、`third_party/MediaCrawler`、凭据、计划任务或浏览器配置。
- V2.0/V2.1 历史包继续按其原 `human_brief` 读取；新字段只能向后兼容。

6. 运行聚焦测试、完整 pytest、compile、CLI/inspect 与 handoff audit。

## 5. 验收标准

1. 新包包含 `昨日热点图文简报.md`，READY `human_brief` 精确指向该文件。
2. 简报顶部一眼可见业务日期、状态、候选数量、配图数量和热度前列事件。
3. 有图事件出现 `![替代文字](images/.../文件)`，路径对应包内真实文件；同时展示图源和人工权利复核提示。
4. 无图事件不出现伪造图片语法，且说明未取得合格图片或不在 Top 3 图片范围。
5. 单条事件不展示矩阵去重结构、分量字典等工程字段；完整字段仍存在于技术审计稿和 JSON。
6. 摘要、要点和来源标题有长度上限，平台文本不能注入额外标题、HTML、图片或任意 Markdown 链接。
7. 热度、排名、故事 ID、图片数量和机器合同内容不因新文档发生变化。
8. 历史包读取兼容，manifest/hash 校验和不可变发布不回归。
9. 2026-08-30 回放预览可生成；由于该包实际图片数为 0，必须诚实显示无合格配图。
10. 聚焦测试、全量测试、编译检查、CLI 检查和 handoff audit 全部通过；若外部图片仍为 0，只能说明渲染能力通过，不能宣称真实配图链路成功。
